# 网关适配层

> 为什么要有这一层：QQ 协议的实现有很多种，SnowLuma 只是其中之一。
> 桥接不该被某一家绑死，换网关时应该**只改配置**。

## 一、目录

```
src/gateway/
├─ index.mjs     工厂：按 config.gateway.type 选适配器，并导出 text()
├─ snowluma.mjs  SnowLuma 官方 SDK 适配（含扩展能力）
└─ onebot.mjs    标准 OneBot v11（NapCat / LLOneBot / Lagrange / go-cqhttp）
```

## 二、统一接口

桥接只依赖这组方法，任何适配器实现它就能用：

| 分类 | 方法 |
| --- | --- |
| 连接 | `connect()` `close()` |
| 事件 | `onEvent(cb)` `onGroupMessage(cb)` `onPrivateMessage(cb)` `onNotice(type, cb)` `onBotStatus(cb)` |
| 发送 | `sendGroupMessage(id, message)` `sendPrivateMessage(id, message)` |
| 查询 | `getLoginInfo()` `getGroupMemberInfo(gid, uid)` `getGroupMemberList(gid)` `getImage({file})` `getMessage(id)` |
| 通用 | `request(action, params)` / `raw(action, params)` |
| 可选 | `fetchFaceEntity(faceId)` |

`text('abc')` 由 `index.mjs` 提供 → `{ type: 'text', data: { text: 'abc' } }`，不依赖任何 SDK。

## 三、SnowLuma 与 OneBot 的差异

| 能力 | SnowLuma | 标准 OneBot v11 |
| --- | --- | --- |
| 收发消息 / 群成员 / 图片 / 消息详情 | ✅ | ✅ |
| 事件订阅方式 | SDK 的 `onGroupMessage` 等 | WS 推送 + `post_type` 分类 |
| `fetchFaceEntity`（QQ 小黄脸实体） | ✅ 有 | ❌ 抛 `code: 'UNSUPPORTED'` |
| 原生模块 | Windows only | 看具体实现 |

**降级策略**：`fetchFaceMedia` 里调用 `fetchFaceEntity` 失败（含 UNSUPPORTED）时，
自动回退到本地"表情 id → 中文名"表（211 条），所以换网关也不会让表情识别功能坏掉。

## 四、配置

```json
"gateway": {
  "type": "snowluma"
}
```

或换标准 OneBot：

```json
"gateway": {
  "type": "onebot",
  "httpUrl": "http://127.0.0.1:3000",
  "wsUrl": "ws://127.0.0.1:3001",
  "accessToken": "可留空"
}
```

- 不写 `gateway` 时按 `snowluma` 处理（兼容旧配置）
- `type` 写错会回退到 snowluma 并在日志提示
- 启动日志会打印一行 `[gateway] 使用 xxx`，排查时先看它

## 五、加一个新网关

1. 复制 `onebot.mjs` 改名
2. 实现上表的方法（事件用 EventEmitter 派发即可）
3. 在 `index.mjs` 的 `createGateway` 里加一个分支
4. 跑 `node --check` + 用假服务写个单测（参考 `qq-bridge-adapt/test-gateway.mjs`）
