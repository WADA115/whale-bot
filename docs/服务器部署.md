# 服务器部署指南

> 目标：把这套机器人从"家里的一台 Windows"搬到"一台长期开着的服务器"。

---

## 零、先说最硬的限制

**SnowLuma 只有 Windows 版。** 它的原生模块是：

```
native\snowluma-win32-x64.node
native\snowluma-win32-x64.dll
native\websocket-win32-x64.node
```

Linux 上跑不起来。所以服务器方案只有两条路：

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **A. Windows 服务器 / VPS** | 整套原样搬，零改动 | Windows VPS 通常更贵 |
| **B. Linux 服务器 + 换网关** | 便宜、稳定 | 要把 SnowLuma 换成 Linux 能跑的 OneBot v11 实现 |

桥接只依赖 **OneBot v11 协议**（HTTP + WebSocket），不依赖 SnowLuma 本身。
所以 B 方案只需要换网关，桥接代码不用改。

Linux 上可选的 OneBot v11 实现（自己评估风险与许可）：

- NapCat（基于 NTQQ，常见）
- LLOneBot
- Lagrange.OneBot
- go-cqhttp（老牌，维护状况需自行确认）

> 换网关后：`config.snowluma.httpUrl` / `wsUrl` 指向新网关即可，
> `snowluma.homeDir` 留空，别用 `start-all` 里的 SnowLuma 启动逻辑。

## 一、方案 A：Windows 服务器（最省事）

### 1. 装环境

| 组件 | 说明 |
| --- | --- |
| Node.js ≥ 20 | 桥接与面板 |
| Python 3.10+ | 简笔画（Pillow）、ASR 服务 |
| DSH | 模型接入，监听本机某端口 |
| SnowLuma | QQ 网关，登录后开 3000/3001 |

### 2. 放代码

```
C:\bot\qq-bridge
```

改 `config.json`：

```json
{
  "ownerQQ": "你的QQ",
  "allow": { "private": ["你的QQ"], "groups": ["你的群"] },
  "snowluma": { "homeDir": "C:\\SnowLuma", "httpUrl": "http://127.0.0.1:3000", "wsUrl": "ws://127.0.0.1:3001" },
  "dsh": { "baseUrl": "http://127.0.0.1:端口" }
}
```

### 3. 开机自启

- SnowLuma：它自带开机项
- 面板 + 桥接：任务计划程序 → 登录时运行 `静默启动.vbs`
- 守护：面板内置，不用额外配

### 4. 远程访问面板（可选，谨慎）

面板默认只听 `127.0.0.1`。要在服务器上远程看：

1. 设环境变量 `QQB_PANEL_ALLOW_REMOTE=1`
2. 用 **Caddy / Nginx 反代 + HTTPS**，不要直接把 3200 暴露公网
3. 只给自己留密钥；需要给别人的话，让他们自己注册普通账户

Caddy 示例：

```
bot.example.com {
    reverse_proxy 127.0.0.1:3200
}
```

## 二、方案 B：Linux 服务器

### 1. 能搬的 / 不能搬的

| 组件 | Linux | 说明 |
| --- | --- | --- |
| `src/bridge.js` | ✅ | 纯 Node，无需改 |
| `app.js` + `public/` | ✅ | 纯 Node |
| `src/sketch.py` | ✅ | 需 `pip install pillow` |
| `src/asr-server.py` | ✅ | 装 sherpa-onnx（`pip install sherpa-onnx`） |
| `tools/ffmpeg` | ❌ | 换成 `apt install ffmpeg`，配置里填 `/usr/bin/ffmpeg` |
| `*.bat` / `*.vbs` / `*.ps1` | ❌ | Windows 专用，见下 |
| SnowLuma | ❌ | 见"零" |

### 2. 启动脚本怎么办

Linux 上用 systemd 或 pm2，别再想着 bat/vbs。

```ini
# /etc/systemd/system/whale-panel.service
[Unit]
Description=Whale panel
After=network.target

[Service]
WorkingDirectory=/opt/qq-bridge
ExecStart=/usr/bin/node app.js
Environment=QQB_DEV_KEY=换成你自己的密钥
Environment=DEEPSEEK_API_KEY=你的key
Restart=always
User=bot

[Install]
WantedBy=multi-user.target
```

桥接同理（`ExecStart=/usr/bin/node src/bridge.js`）。

`app.js` 里监听地址目前写死 `127.0.0.1`；要在 Linux 上对外提供，用 Nginx/Caddy 反代，
或者把那一行改成 `0.0.0.0` 并把来源 IP 白名单一起改（不推荐直接裸奔）。

### 3. 路径注意

以下都已改成"配置驱动"，迁移时只改配置：

- `socialV2.voice.ffmpegPath` → `/usr/bin/ffmpeg`
- `snowluma.homeDir` → 留空（用外部网关）
- `role.developers`、`allow.*` → 换成新的

## 三、开源前检查清单

`开源打包.ps1` 已经帮你做了一部分，发布前再确认：

- [ ] `state\` 不在仓库里（`.gitignore` 已忽略）
- [ ] `config.json` 不在仓库里（只提交 `config.example.json`）
- [ ] 代码里没有开发者密钥（已改成 env → `state/dev-key.txt` → 自动生成）
- [ ] 代码里没有 QQ 号、群号、token、API key
- [ ] 没有个人报告（打包脚本已排除 `*.docx`、`功能报告.*` 等）
- [ ] `LICENSE` 保留（MIT，原作者 Derpyu520 与贡献者）
- [ ] README 写清：依赖、启动、许可证、免责声明

打包命令：

```powershell
cd <旧位置>\qq-bridge
powershell -ExecutionPolicy Bypass -File 开源打包.ps1
# 产物默认在 ..\release\qq-bridge-<日期>\
```

## 四、服务器安全清单

- [ ] 面板**不要**直接暴露公网；要暴露必须 HTTPS 反代
- [ ] 开发者密钥用环境变量，别提交进仓库
- [ ] 面板账户密码 ≥ 12 位；普通账户只给熟人
- [ ] `state\` 权限收紧（Windows: icacls 仅本人；Linux: chmod 700）
- [ ] 出站内容审核保持开启
- [ ] 定期备份 `state\`（程序每天自动备到 `state\backup\`，保留 7 天）
- [ ] 关注 QQ 账号风控风险（第三方协议登录）

## 五、迁移到新机器（同 Windows）

一条命令：

```powershell
cd <旧位置>\qq-bridge
powershell -ExecutionPolicy Bypass -File 迁移.ps1 -Target "D:\新位置"
```

它会停服务、复制、修残留绝对路径、重建桌面快捷方式、自检并启动。
`state\` 一起搬走，账户/记忆/日志都在，密码不用重设。
